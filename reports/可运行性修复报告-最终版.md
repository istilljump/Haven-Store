## 二、本次发现并修复的问题（按严重程度）

### P0-1 Mapper XML 用裸 `<` 导致 XML 解析失败 → 后端启动即崩

- 文件：`backend/src/main/resources/mapper/ProductMapper.xml`
- 现象：`SAXParseException: 元素内容必须由格式正确的字符数据或标记组成`，`Failed to parse mapping resource: ProductMapper.xml`，Spring 容器起不来。
- 原因：SQL 中 `distance <= #{radius}`、`) <= #{radius}` 的 `<` 未转义。
- 修复：改为 `&lt;=`（2 处）。

### P0-2 XML 用了 SQL Server 语法 → MySQL 执行报错

- 同上文件：`product p WITH (INDEX(idx_longitude, idx_latitude))`
- 修复：改为 MySQL 语法 `product p FORCE INDEX (idx_longitude)`（2 处）。

### P0-3 Mapper 接口与 XML 参数不匹配 → 附近商品接口 501

- 现象：`BindingException: Parameter 'offset' not found`、`Parameter 'status' not found`
- 原因：XML 里写了 `#{offset}`，但 `ProductMapper.selectNearbyProducts` 只声明了 `pageNum/pageSize`（Service 里算了 `offset` 却没传）；
  `selectNearbyProductCount` 的 XML 用了 `#{status}`，接口里根本没这个参数。
- 修复：
  - `ProductMapper.selectNearbyProducts(...)` 增加 `@Param("offset") Integer offset`，`ProductServiceImpl` 传入已算好的 `offset`；
  - `ProductMapper.selectNearbyProductCount(...)` 增加 `@Param("status") Integer status`，Service 传 `ProductStatusEnum.ON_SHELF`。
  - 同步修正 2 个测试类里 Mock 的参数个数（3 处）。

### P0-4 `mvn package` 编译失败（测试代码）

| 文件 | 问题 | 修复 |
|---|---|---|
| `ProductAIServiceSimpleTest.java` | 用了 `@DisplayName` 没有 import | 补 `import org.junit.jupiter.api.DisplayName;` |
| `ProductServiceSimpleTest.java` | 同上 | 同上 |
| `Result.java`（主代码） | 测试调用 `result.isSuccess()`，但 `Result` 没有该方法 | 新增实例方法 `isSuccess()`（判断 `code == 200`） |
| `ProductServiceFullTest.java` | 用了 `any()` / `when()` 没有静态导入 | 补 `import static org.mockito.ArgumentMatchers.any;`、`import static org.mockito.Mockito.when;` |

### P1-1 管理后台登录接口缺失 → 已补齐（复用性最高的方案）

- 新增 `backend/src/main/java/com/example/admin/controller/AdminController.java`
- 设计：`POST /api/admin/login` **不重复实现登录逻辑**，直接调用 `UserService.login(dto)`，复用密码比对 / 状态校验 / JWT 签发 / Redis 缓存，只额外做一次角色判断（`isAdmin` 必须为 true，否则 403）。
- 配套：`User` 实体增加 `role` 字段、`UserConstant.ROLE_ADMIN/ROLE_USER`、`LoginUserVO.isAdmin`、注册时默认 `role=0`。
- 好处：以后登录规则变化只改 `UserServiceImpl.login()` 一处，用户端与管理端自动同步。

### P1-2 管理接口可被普通用户越权访问

- 现象：普通用户 token 也能拿到 `/api/admin/stats` 数据（实测 HTTP 200）。
- 修复（复用性高的做法）：新增 `backend/src/main/java/com/example/admin/interceptor/AdminAuthInterceptor.java`，在 `WebMvcConfig` 里统一注册：
  - `addPathPatterns("/admin/**")` + `excludePathPatterns("/admin/login")`
  - 校验顺序：未登录 401 → 账号不存在/被禁用 401 → 非管理员 403
- 好处：`/admin/**` 下**以后新增任何接口自动受保护**，不用每个方法手写权限判断。

### P1-3 管理后台统计接口是 TODO 占位，永远返回 0

- 文件：`AdminController.getSystemStats()`
- 修复：接入 `UserMapper` / `ProductMapper` 做真实统计（总用户数 / 正常用户数 / 总商品数 / 上架商品数）。

### P1-4 Dockerfile 复制 jar 文件名不匹配 → `docker build` 必失败

- 文件：`backend/Dockerfile` 第 34 行
- 现象：`COPY --from=builder /build/target/secondhand-market-*.jar app.jar`，但 Maven 实际产物是 `second-hand-market-1.0.0.jar`（artifactId 带连字符）。
- 修复：改为 `COPY --from=builder /build/target/*.jar app.jar`（版本号变化也不会失效，`.jar.original` 不会被匹配）。

### P2 本机环境变量覆盖端口（非项目问题，但会让人以为"跑不起来"）

- 现象：直接用 `java -jar` 启动时，报 `Port 2083 is already in use`，而 `application.yml` 明明写的是 8080。
- 原因：当前系统环境变量里存在 `SERVER__PORT=2083`，被 Spring Boot 宽松绑定读取，覆盖了配置文件。
- 处理：启动时显式指定 `--server.port=8080` 即可（命令行参数优先级最高）。
- 影响范围：**只影响你这台机器**，别人 clone 后不受影响。
