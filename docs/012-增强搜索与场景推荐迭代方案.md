# 012 · 第二轮迭代：增强搜索 × 场景化推荐 × 数据飞轮闭环（方案与交付记录）

> 定位：**核心招牌（数据驱动定价 + 校园 LBS）→ 配套增强层（增强搜索 + 场景推荐）→ 数据飞轮（成交回流行情）**。
> 本轮回答：「招牌之外的体验是否落回电商标配？」——搜索与推荐全部锚定校园闲置、成交行情、校区三要素。

## 一、迭代目标与约束

目标：搜索不再只是标题 LIKE（补全/纠错/行情标签/埋点），推荐抛弃「最新/热门」改为五条校园规则（R1~R5），
每条推荐强制携带可解释文案；首页行情看板 + 一键飞轮演示让「成交越多估价越准」现场可见。

约束：复用不推翻（/product/search 保留，新端点并行）；新模块独立（`com.example.search` / `com.example.recommend`）；
零外部接口（纠错全靠本地词表）；必做/进阶分离（成色二次筛选挂开关缺省关）；370 冒烟 / 73 单测为底线不回退；
推荐总开关接入后台设置；老库配置缺字段按缺省值处理。

## 二、搜索方案（模块 com.example.search）

数据模型（4 张新表，全库 14 → 18 张）：

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `search_suggest_word` | 补全词库（静态种子，可运营） | word / word_type / tag_label（【教材】【数码】）/ pinyin（全拼+首字母）/ status |
| `search_correction` | 纠错词表 | wrong_word / correct_word / type(PINYIN/SHAPE)，种子约 30 条 |
| `category_relation` | 互补品类字典（归属推荐域） | category_id / related_category_id / weight / note |
| `search_log` | 搜索埋点 | user_id(可空) / keyword / corrected_keyword / campus_id / result_count / clicked_product_id / deal_flag |

接口：`GET /search/suggest`（词库前缀 > 拼音前缀 > 本校热搜排序，候选 ≤8 词实时算「本校近期成交 N 件」）、
`GET /search/products`（纠错 → 复用 ProductService.searchProducts → 批量行情标签 → 写埋点，返回 correction/page/logId，
productCondition 仅在开关开启时生效）、`POST /search/log/click`（点击信标）、`GET /search/log/list`（演示/验证用）。

词表加载方案：词库表只存静态字典，**成交热度与本校热度全部运行时统计**——每笔成交自动反映到补全权重与标签，
无需离线重建；纠错宁可不纠不可错纠（仅精确/包含命中药表）。

## 三、推荐方案（模块 com.example.recommend）

| 规则 | 位置 | 触发 | 排序 | 兜底 | 文案 |
| --- | --- | --- | --- | --- | --- |
| R1 校区成交活跃 | 首页 | 校区上下文 | 近90天校区成交件数 desc 的品类 → 品类内在售 | → R2 | 「{校区}近期成交活跃」 |
| R2 本校高频品类 | 首页第二梯队 | 同上 | 高频品类在售最新 | → 校区最新在售 | 「本校同学常出【{品类}】闲置」 |
| R3 互补闲置 | 搜索底部 | 互补字典命中 | weight desc → 品类成交 desc | 未命中→不展示 | 「经常和「{词}」一起交易」 |
| R4 同校同款 | 详情页 | 校区/品类/成色 | 同校区+品类+成色 → 同校区+品类 → 同品类 | → R5 | 「同校区·{成色}·同类闲置」 |
| R5 详情页互补 | 详情页第二梯队 | 字典命中 | weight desc | 无 | 「经常和该商品一起交易」 |

接口：`GET /recommend/home`、`GET /recommend/complementary`、`GET /recommend/for-product/{id}`；统一排除自身/已售出/本人商品/搜索结果已含商品；每处 ≤4 条；总开关 `trade.recommendEnabled`（缺省开）。

## 四、联动闭环

- 首页「本校行情速览」卡片：`GET /market/campus-summary?campusId=` → TOP3 品类 + 成交件数 + 中位价，手动刷新。
- `scripts/demo_flywheel.py`：走真实 API 打印 before（行情/看板）→ 发布+搜索+点击+下单+支付 → after（样本量+1、中位价重算、deal_flag 归因）——数据飞轮现场可见，且冒烟用相对断言锁定（before N → after N+1）。
- 支付成功后 `OrderServiceImpl.pay` 调 `searchLogService.markDeals` 回写 7 天内点击命中（事务外 try/catch，order→search 单向依赖）。
