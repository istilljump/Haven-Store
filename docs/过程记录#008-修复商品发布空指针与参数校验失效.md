# 过程记录#008 - 修复商品发布空指针与参数校验失效

## 1. 问题背景
在商品发布功能的第三轮迭代中，测试发现了两个关键Bug：
1. 选择线上交易、不填经纬度时，保存方法抛出NullPointerException
2. 价格输入0或负数时，校验没有生效，依然能提交成功

## 2. 问题定位

### 2.1 线上交易经纬度NPE问题
- **现象**：选择线上交易模式时，如果不填写经纬度，保存方法抛出NullPointerException
- **根因**：线上交易模式理论上不需要地址信息，但代码中未对线上交易模式做特殊处理，导致经纬度字段为null时触发NPE
- **影响**：线上交易场景无法正常发布商品

### 2.2 价格校验失效问题
- **现象**：价格输入0或负数时，JSR-303校验未生效，依然能成功提交
- **根因**：Controller层参数校验（@Valid）只验证DTO参数，但Service层在业务处理前未做二次校验
- **影响**：存在脏数据风险，不符合业务规则

## 3. 修复方案

### 3.1 线上交易经纬度处理
在`ProductServiceImpl.buildProduct()`方法中增加逻辑：
```java
// 线上交易时强制清空地址、经纬度，避免脏坐标入库
if (ProductConstant.TRADE_TYPE_ONLINE.equals(dto.getTradeType())) {
    product.setAddress(null);
    product.setLongitude(null);
    product.setLatitude(null);
}
```

### 3.2 价格Service层兜底校验
在`ProductServiceImpl.addProduct()`方法中增加价格校验：
```java
// 价格Service层兜底校验，防止Controller层校验失效
if (dto.getPrice() == null || dto.getPrice().compareTo(BigDecimal.ZERO) <= 0) {
    throw new BusinessException(400, "商品价格必须大于0");
}
```

## 6. 经验总结

### 6.1 防御性编程
- **多层校验**：Controller层参数校验 + Service层业务校验，双重保障
- **空值处理**：对可选字段做显式null处理，避免NPE
- **业务规则校验**：关键业务规则在Service层做兜底校验

### 6.2 测试策略
- **边界测试**：覆盖正常值、边界值、异常值
- **场景测试**：线上/线下交易模式分别测试
- **Mock测试**：模拟依赖服务，专注被测逻辑

### 6.3 代码质量
- **常量管理**：使用ProductConstant管理交易类型
- **异常处理**：统一BusinessException，携带明确错误信息
- **日志记录**：关键操作记录日志，便于问题排查
