# 015 · 业务流程升级迭代方案（轮 8 · 交易闭环四亮点）

> 审定方式：引导式审定 9 项（方向/通知设计/议价规则/面交码/评价范围/Schema/测试/前端/验收），全部结论经用户确认后实施。
> 基线：UI 轮 7 `e5c3c2e`。前置勘查：交易链路三大薄弱环节（通知断链 / 聊天不承接交易 / 订单终态无闭环），证据 file:line 见勘查记录。

---

## 一、四大亮点总览

| 亮点 | 解决的问题 | 核心机制 |
|---|---|---|
| ① 交易事件通知中心 | 交易全程零通知，`message_type=3` 空壳 | 拉取式交易消息：六类事件定向写入 system_message（type=3），复用通知中心+角标 |
| ② 收藏联动提醒 | 收藏与改价/售出零联动 | 降价/售出事件通知收藏者（按商品+标题去重），售出文案引导同校同款（R4） |
| ③ 私信议价一键下单 | 聊天谈价与订单割裂 | 卖家会话内发报价（30 分钟时效）→ 买家一键接受按议价价下单，成交快照回流行情 |
| ④ 面交码 + 终态闭环 | 完成仅靠买家手动确认 | 支付生成 6 位码 → 卖家输码确认交付（双路径）→ 7 天自动完成兜底 |

## 二、交易事件矩阵（通知中心）

| 事件 | 通知谁 | 标题 | 去重 |
|---|---|---|---|
| 下单锁定 | 卖家 | 你的商品有人下单了 | 事件天然一次 |
| 下单锁定 | 收藏者 | 收藏的「商品」已被买走 | 锁定事件天然一次；排除买家本人 |
| 支付成功 | 买家 | 支付成功，面交码已生成 | 含 6 位码与规则说明 |
| 支付成功 | 各卖家 | 你的商品已售出，待面交 | 按明细卖家分组 |
| 买家取消 | 卖家 | 订单已取消，商品已回架 | 事件天然一次 |
| 超时取消 | 买家 | 订单超时未支付已取消 | 定时任务逐单 |
| 确认完成 | 卖家 | 订单已完成 | 含评价引导文案 |
| 卖家输码 | 买家 | 面交完成，订单已交付 | 含评价引导 |
| 超时自动 | 双方 | 订单已自动完成 | 定时任务逐单 |
| 卖家降价 | 收藏者 | 收藏的「商品」降价了 | 标题含商品名 + 未读去重 |
| 收到报价 | 买家 | 收到议价报价 | 事件天然一次 |

实现：`TradeNotifyService/Impl`（message 模块），`message_type=3`、`receiver_type=user`；批量走 saveBatch(500)。接入点：`OrderServiceImpl`（create/pay/cancel/confirmFinish/cancelTimeoutOrders/autoFinish）、`PrivateMessageServiceImpl`（sendOffer/acceptOffer）。全部 try/catch——通知失败只告警，不影响主事务。

## 三、私信议价规则（审定项 3）

- 仅**卖家**可发报价（定价权在卖家）；报价须 `>0` 且 `< 商品现价`
- 报价有效期 **30 分钟**（与订单待支付超时对齐）；同会话旧待处理报价自动失效
- 失效联动：报价被接受 / 商品被任何买家锁定（CAS 下单）/ 过期 → `offer_status=2`；接受接口内再做在售校验兜底
- 买家一键接受 → `OrderService.createFromOffer(productId, buyerId, price)`：与购物车下单同语义（CAS 锁定/明细快照/移出购物车/事件通知），**成交快照价=议价价**，随支付回流行情样本（议价也是真实成交）
- 总开关：后台「交易设置 → 议价功能」（`tradeNegotiationEnabled`，缺省开）
- 消息表落法：`private_message` 复用，`offer_price/offer_expire_time/offer_status` 三字段

## 四、面交码与订单终态（审定项 4）

- 支付成功即生成 **6 位数字确认码**（订单级；总开关 `tradeConfirmCodeEnabled` 关闭时不生成）
- **可见性**：仅订单买家本人 + 已支付状态在订单详情下发（卖家通过买家出示获得）
- **双路径完成**：买家确认收货（`confirmed_by=1`）/ 卖家输码（`confirmed_by=2`，`POST /order/{orderNo}/confirm-code`）任一即完成
- **防滥用**：错码累计 `confirm_fail_count`，达 5 次锁定卖家输码路径（买家路径不受影响）
- **兜底**：支付 7 天未确认 → 定时任务自动完成（`confirmed_by=3`），复用 10 分钟轮询框架，逐单条件更新与人工操作互斥

## 五、评价标签与回评（审定项 5）

- 买家评价可勾选预置正向标签（≤3）：准时赴约 / 成色如一 / 沟通顺畅 / 描述相符；白名单校验（`CommentTagConstant`），逗号落库 `comment.tags`
- **卖家回评**：每条评价仅一条（`comment.reply/reply_time`），仅商品发布者可回，≤500 字；评分公式不变
- 信用接口新增 `topTags`（卖家全部正常评论标签计数 Top3），详情页徽章悬浮展示

## 六、Schema 与开关

- `backend/sql/05-upgrade.sql`：三表加列（幂等，`hs_add_column` 过程检查 information_schema）；`01-schema.sql` 已同步
- 新增开关：`tradeNegotiationEnabled` / `tradeConfirmCodeEnabled`（trade 分组 JSON，无 DDL），设置页可配
- 老数据兼容：全部新列 NULL/默认值，不触碰既有行为

## 七、端到端演示路径

1. **通知**：testuser1 下单购买 testuser2 在售商品 → testuser2 通知中心出现「你的商品有人下单了」；支付 → 双方各收到支付/面交码通知
2. **议价**：testuser2 在与 testuser1 的商品会话中点「报价」（低于现价）→ testuser1 收到报价卡片（倒计时）与交易通知 → 点「接受报价并下单」→ 自动创建订单并跳转订单页
3. **面交码**：testuser1 支付 → 订单详情出现面交码卡片；testuser2 在「我卖出的」输码 → 订单完成（双方收到完成通知）
4. **收藏提醒**：testuser2 收藏某商品 → 卖家采纳降价建议改价 → testuser2 收到「收藏的商品降价了」
5. **评价标签**：testuser1 确认收货后评价勾选标签 + testuser2 回评 → 商品详情/信用徽章展示标签
