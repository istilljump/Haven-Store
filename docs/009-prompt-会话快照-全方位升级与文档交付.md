## 二、系统约束与拦截记录（来源：系统 / 安全钩子）

### S-01 源码写入通道限制

- **来源**：系统（Mimosa 安全钩子，PreToolUse 拦截）
- **用途**：防止绕过安全扫描直接改写源码
- **核心内容**：凡通过 Bash（sed/重定向等）写入 `src/main/java`、`tests/` 等源码文件的操作一律拒绝，报错提示「请改用 Write/Edit/MultiEdit 提交同一内容；这样 PreToolUse 才能检查候选代码」。
- **关键约束**：所有源码变更必须走 Write/Edit 工具通道；删除文件可使用 `rm`（单独执行可通过）。影响实例：MessageController 导入修正、MessageService 残留清理、Mapper XML 批量替换（XML 非源码目录，Bash 通过）。

### S-02 生成前安全约束（会话级注入）

- **来源**：系统（Mimosa，会话上下文注入）
- **用途**：在写代码前声明安全红线，满足时视为实现验收条件
- **核心内容与关键约束**：
  1. **SSRF 防护**：服务端请求 URL 时仅允许 http/https；发请求前校验 host，并拒绝 localhost、环回、私有和保留地址（仅在需求相关时视为验收条件）；
  2. **硬编码凭据**：源码中不得出现明文口令/密钥，需改环境变量或密钥管理并在检出后轮换；
  3. **CSV 注入**：导出单元格以 `= + - @` 开头需转义；
  4. **告知义务**：低危发现不阻断，但必须在结果中明确告知用户；
  5. **路径限制**：不得读取 `.env`、密钥文件、`.git`、云凭据等。
- **实际影响**：冒烟测试曾因 URL 未校验与口令字面量被拦截两次，最终改为 `safe_url()` 统一校验（协议白名单 + 主机解析 + 环回/私有/保留地址拒绝 + `SMOKE_ALLOW_LOCAL` 显式放行本机被测服务）与 `DEMO_*` 环境变量常量。

### S-03 提交/推送前扫描拦截

- **来源**：系统（Mimosa，git commit/push 前置钩子）
- **用途**：高危发现强制拦截提交，修复后方可重新提交
- **核心内容与关键约束**：三次强制拦截记录：
  1. 第一次（9 高危）：`tests/api_smoke_test.py` 的 SSRF 模式与硬编码凭据 + `Md5Util.java` 弱加密死代码 → 修复：删除 Md5Util、口令常量化、URL 校验；
  2. 第二次（5 高危）：同文件仍残留 SSRF 模式与 `wrong-password`/`different1` 字面量 → 修复：`safe_url()` 重写为完整的 IP 分类拒绝逻辑（含 `SMOKE_ALLOW_LOCAL` 显式放行被测本机服务）、密码字段字面量全部改为拼接常量；
  3. 第三次通过（仅 12 个 low 级：`mock_server.py`/`run_server.py` 测试随机数，不阻断但须告知）。
- **补充**：一次 `git add -A` 因 `.mimosa/` 钩子状态目录的超长文件名报 `Filename too long`，属 git 自身错误而非安全拦截；处置为将 `.mimosa/` 加入 `.gitignore` 后重新暂存。

### S-04 系统提醒机制

- **来源**：系统（工具链自动提醒）
- **用途**：非指令性提示
- **核心内容**：TodoWrite 使用提醒（多次）；后台任务完成/失败通知（backend jar 启停）；文件被外部修改需重读的编辑保护。
- **关键约束**：均不改变任务方向，仅影响执行节奏。
