# 013 · 五轮迭代评估与裁定记录（2026-11）

> 方法论：**引导式迭代**——每轮开始先做差距评估（现状证据 → 候选项 → 裁定），
> 实施后立即全量回归（单测 + 冒烟 + 构建），再进入下一轮。
> 本文档记录轮 3~5 的动态评估、裁定与交付；轮 2 见 docs/012。

## 一、轮 2：增强搜索 × 场景推荐 × 数据飞轮（已批准方案，docs/012）

**评估**：核心招牌（行情估价 + 校园 LBS）落地后，搜索仍是标题 LIKE、推荐是「最新/热门」凑数——招牌之外的体验落回电商标配。
**裁定**：搜索补全/纠错/行情标签/埋点 + 五条校园规则推荐（R1~R5）+ 行情看板 + 飞轮演示脚本。
**交付与验收**：search/recommend 双模块、4 张新表（全库 18 张）、demo_flywheel.py；
冒烟 370 → **409**、单测 73 → **92**，前端构建通过。

## 二、轮 3：行情趋势可视化

**评估**：行情已进估价/搜索/看板，但「走势」不可见——详情页只有静态中位价，「定价大脑」缺最后一块可视化拼图；ECharts 已在依赖中可复用。
**裁定**：`GET /market/trend`（按日聚合件数+中位价，日期升序确定性契约）+ 详情页行情卡内嵌 ECharts 迷你折线（动态 import 惰性加载）；不做管理端行情页（数据量小、边际价值低——做减法）。
**交付与验收**：单测 +2（聚合/降级）→ 94 全绿；冒烟章节 36 +5 项（趋势形状/升序/与 summary 对账/非法窗口）→ **414** 全绿。修复一处实现 bug：聚合点显式按日期排序（单测锁定）。
**提交**：d8d0d9c

## 三、轮 4：卖家信用画像（可信交易轻量层）

**评估**：面交二手的信任短板——买家只看到昵称，无历史信用可参考；完整的信用体系（担保交易/仲裁台）工作量过大，与「轻量」定位不符。
**裁定**：**确定性公式**的轻量信用分（无新表、无外部信用服务）：
`基线60 + 近90天成交×3 +（评价均分-3）×10 - 有效举报×5，夹取[0,100]`；无成交卖家固定「待积累」。
`GET /credit/{userId}` 游客可用；详情页内嵌 sellerCredit 徽章。不做担保交易/仲裁台（超出本轮定位——明确不做）。
**交付与验收**：单测 +5（公式精确值）→ **99** 全绿；冒烟章节 37 +8 项 → **422** 全绿。
修正两处测试期望错误（66/61 分对应等级「一般」）。依赖方向修正：信用服务放 product 模块避免 user↔product 循环依赖（Spring Boot 2.6+ 默认禁止循环引用）。
**提交**：e7b6768

## 四、轮 5：性能收口与文档归位

**评估**：① 搜索/推荐为高频读路径，词库静态 + 统计数据 5 分钟内可视为稳定 → 短 TTL 缓存收益明确；
② 四轮迭代后文档口径（README/CI）仍停在上轮，叙事未归位——「估价/LBS=核心招牌，搜索/推荐/趋势/信用=配套增强层」。
**裁定**：suggest/recommend 接 5 分钟 Redis 缓存（null/空结果不缓存，`unless` 防止 disableCachingNullValues 报错；
开关关闭返回 null 永不落缓存）；不做全站缓存治理与 N+1 大清扫（行情标签已批量化，其余路径量级小——做减法）。
**交付**：CacheConfig 新增 searchSuggest/recommend 缓存组（TTL 5 分钟）；docs/013 + README v2.0 口径统一（422/99/18 表）；CI 注释同步。
**风险与边界**：缓存 TTL 5 分钟意味着「成交后推荐排序最多延迟 5 分钟刷新」——看板与行情接口保持实时（飞轮演示不受影响），
已在 README 注明；开关关闭时接口返回 null 且不落缓存，冒烟断言已覆盖。
